# 文件打字模拟器

把内容像真人打字一样**逐字敲进"光标所在的输入框"**——网页输入框（包括**禁止粘贴**的答题框）、聊天窗口、记事本、VSCode、Word 都可以。

本文档描述**当前版本的全部功能**；相比最初版本（2026-10-25）改了什么、修了什么、删了什么，见 [CHANGELOG.md](CHANGELOG.md)。

## 功能一览

| 功能 | 说明 |
|---|---|
| **四种输入方式** | **消息**（默认推荐）/ 逐字模拟 / 真实按键 / 粘贴——针对不同程序各有覆盖，详见「使用方法」 |
| **消息直投（默认）** | PostMessage `WM_KEYDOWN/WM_CHAR` 直投目标窗口消息队列：**免焦点、免前台**，用户点着别的窗口照样打；网页（含禁止粘贴的答题框）、微信等自绘输入框都能进；不带"注入"标记，键盘钩子/输入过滤拦不到 |
| **真实按键** | 按真实扫描码敲键；自动把目标输入法临时切英文、敲完还原（避免被拼音输入法组字错字） |
| **粘贴** | 剪贴板 + Ctrl+V 分批粘贴，自动保存/还原原剪贴板，换行不触发聊天窗"回车发送" |
| **目标窗口锁定** | 开打那一刻锁定目标窗口，状态栏显示目标标题 |
| **焦点被抢自动夺回** | 四级兜底（AttachThreadInput 绑前台线程 → Alt → SwitchToThisWindow → 真实鼠标点击）；夺不回就跳字计数，**绝不把字打进别的程序** |
| **等待目标状态** | 点开始时光标还在本程序上时提示"请点击输入框"，点到目标自动开打；等待中点演示框直接在演示框打字（点哪打哪） |
| **速度精确控制** | 「打字设置」区输入框**直接键入每秒字符数**（1–500），或拖动滑条，两者双向同步；另有"模拟抖动"更像真人、"硬输入"不限速直灌 |
| **吐字稳定性加固** | 每个字的按下+弹起合并为一次 `SendInput` 原子发出（不拆半截键）；硬输入微批次节流不灌爆慢程序 |
| **换行方式选项** | Shift+回车（默认，聊天窗不发送）/ 真回车 |
| **窗口置顶开关** | 默认开启，切页面仍浮在最上层 |
| **开打前点击目标** | 可选（默认关），帮真实按键/粘贴方式落一次光标 |
| **权限自检与警告** | 启动自检完整性级别（低完整性=被 Windows 降权、打不进任何程序，状态栏红字+日志说明）；开打时对比目标进程权限 |
| **高 DPI 支持** | PerMonitorV2 感知清单 + 按真实 DPI 缩放，125%/150% 屏不发虚 |
| **诊断日志** | `%LOCALAPPDATA%\TyperSimulator\typer_debug.log`：版本/完整性/DPI/每次开打的模式/目标句柄标题/按键发送成败数 |
| **发送成败计数** | SendInput/消息发送返回值检测（曾"假成功"——API 说成功但字没到，现在失败会计数、状态栏可见） |
| **自检与测试** | `--selftest` 编码/引擎自测、`--e2e` 六场景真实窗口端到端、tests/ 全套自动测试 |
| **支持文件读取** | .txt/.c/.h/.cpp/.cc/.cxx/.hpp/.py/.docx，编码自动识别 UTF-8/UTF-16/GBK |

## 目录结构

```
typing_simulator/
├── app/                          # 应用本体：源码 + 成品
│   ├── TyperSimulator.py         # 源码（单文件，纯标准库，无第三方依赖）
│   └── 打字模拟器.exe            # 编译好的独立可执行（分发只需这一个文件）
├── tests/                        # 测试与开发工具
│   ├── _target_app.py            # e2e 用的跨进程目标窗口小程序
│   ├── _gui_flow_test.py         # GUI 全流程自动测试（场景 A–E）
│   ├── _probe_web.py             # 「禁止粘贴网页」打字实验（本地 HTTP 验证字真进了网页）
│   ├── _run_tool.py              # 构建辅助（受限环境里跑 pip/PyInstaller 用）
│   └── dpi.manifest              # PerMonitorV2 DPI 感知清单（打包时嵌入 exe）
├── README.md                     # 本文档：当前功能与使用
├── CHANGELOG.md                  # 更新日志：相比最初版本（2026-10-25）的全部变化
└── .gitignore
```

`build/`、`dist/`、`.pydeps/`、`*.exe` 均被 `.gitignore` 排除——git 里只放源码和文档，exe 发版传 GitHub Releases 即可。

## 运行

- **把 `app/打字模拟器.exe` 复制到一个普通文件夹，再双击或用桌面快捷方式**。
  ⚠ 如果 exe 所在的文件夹被打上了 Windows 的**低完整性标签**（个别受保护/沙箱目录会这样），那个文件夹里的 exe 双击就会被系统降权，**发出的一切按键/消息都会被 Windows 拦截**（就是"怎么都打不进字"的根因）。复制到普通文件夹就自动恢复正常权限；程序启动时会自检并在日志/状态栏提示（`integrity=0x2000` 正常，`0x1000` 被降权）。
- 运行临时文件放系统临时目录（`%TEMP%`），日志固定写在 **`%LOCALAPPDATA%\TyperSimulator\typer_debug.log`**——exe 所在文件夹里不会生成任何文件。
- 从带标签的文件夹往外搬 exe 要用**复制**（同盘拖动会把标签一起搬走）。
- 有 Python 时也可以：`python app/TyperSimulator.py`
- 源码自测：`python -X utf8 app/TyperSimulator.py --selftest`
- 端到端测试：`python -X utf8 app/TyperSimulator.py --e2e`（弹出测试窗口，验证按键确实打进目标程序、焦点被抢会自动夺回）

## 拷给其他电脑

只需拷 `打字模拟器.exe` **这一个文件**（纯标准库单文件打包，Win10/11 x64 免装 Python）。注意：

- 首次运行可能弹 SmartScreen"已保护你的电脑"→ 点"更多信息"→"仍要运行"（新文件没有信誉记录的正常现象）
- `打字模拟器.exe` **未做数字签名**；如手上有代码签名证书，按文末命令可签名

## 支持的文件与编码

| 类型 | 后缀 | 编码 |
|---|---|---|
| 文本 | `.txt` | UTF-8 / UTF-8 BOM / UTF-16 / GBK（自动识别） |
| C 语言 | `.c` `.h` | 同上 |
| C++ | `.cpp` `.cc` `.cxx` `.hpp` | 同上 |
| Python | `.py` | 同上 |
| Word | `.docx` | 自动提取正文 |

ASCII 是 UTF-8 的子集，天然支持。旧版 `.doc` 不支持，程序会提示"另存为 .docx 或 .txt"。

## 使用方法

**方式一：选文件** —— 点 **选择文件…**，内容进入左侧内容框（框里显示识别出的编码）。

**方式二：直接粘贴** —— 复制任意文本，点上方内容来源区的 **粘贴剪贴板**（或直接在框里 Ctrl+V / 手动编辑），框里是什么就打什么。

然后：

1. 在「打字设置」区调好参数：**每秒字符数**（输入框直接键入，或拖动下面的滑条，默认 15，上限 500）、**模拟抖动**（更像真人）、或勾 **硬输入**（不限速全速直灌、内置微批次节流不丢字，勾上后速度和抖动失效）
2. 选 **输入方式**（四选一，默认**消息**）：
   - **消息**（推荐）：把字符消息直接投进目标窗口的消息队列——**免焦点、免前台**；网页（包括**禁止粘贴**的答题框）、微信等自绘输入框都能进；不带"注入"标记，键盘钩子/输入过滤拦不到
   - **逐字模拟**（普通程序）：合成字符事件，中英文都行，绝大多数普通程序通用
   - **真实按键**（英文字符兼容）：像真人一样按键盘按键；会自动把目标窗口的输入法临时切成英文再敲、敲完还原，避免被输入法打错字
   - **粘贴**（大段文本快）：剪贴板 + Ctrl+V 分批粘贴；换行是文本换行，**不会**触发聊天窗口的"回车发送"
   - 「选项」区勾选 **换行用 Shift+回车** 可避免聊天窗口"回车发送"（网页多行框同样换行）；给单行框打多行请去掉勾选用真回车
   - 勾选 **开打前点击目标一下** 会在打字前帮你点一下目标（消息方式不需要，也别勾——免得动了你放好的光标）
   - 勾选 **窗口置顶** 让程序窗口一直保持在最上层（切到别的页面/窗口也看得见），默认开启，不想要就取消
3. 点 **开始 (F6)**（或直接按 F6）
4. 倒计时期间，**用鼠标点一下你要打字的那个输入框**（让光标停在那里）
5. 倒计时结束那一刻的窗口会被**锁定为目标窗口**，状态栏显示"正在打字 → 窗口标题"，内容随即敲进去
   - 消息方式下**什么都不用点**——你点好输入框（光标停在那里）就行，程序不动你的鼠标和焦点；其他方式可勾"开打前点击目标一下"帮着落一次光标
   - 打字过程中焦点即使被抢走（比如误点了本程序），也会**自动把焦点夺回目标窗口**继续敲，字不会跑到别的程序里
   - 如果点开始时焦点还在本程序上（还没点到目标输入框），会进入**等待目标**状态：状态栏提示"请点击要打字的输入框…"，等你点到目标输入框的那一刻**自动开打**——绝不会把字打进本程序自己的窗口里（此时按 F6 或 Esc 可取消）
   - 等待中**直接点右侧内置演示框**，会立刻在演示框里打字（点哪打哪）；或者先把模式切到"内置演示框"再点开始

想先在本程序里看看效果：把模式切到 **内置演示框**，内容会打在右侧演示框里。

## 快捷键（全局，任何窗口里都有效）

| 键 | 作用 |
|---|---|
| F6 | 开始 / 暂停 / 继续（倒计时或等待目标时按 = 取消） |
| Esc | 停止 |

## 出问题先看日志

程序运行时会把记录写在 **`%LOCALAPPDATA%\TyperSimulator\typer_debug.log`**：启动的版本号、完整性级别、每次开打的模式/速度、锁定到的窗口句柄和标题、按键发送成功/失败数。打不进字时，把这个文件最后几行发给开发者，就能一眼定位断在哪一环。

## 开发与构建

```bash
# 源码自测 / 端到端（在 typing_simulator/ 目录下执行）
python -X utf8 app/TyperSimulator.py --selftest
python -X utf8 app/TyperSimulator.py --e2e
python -X utf8 tests/_gui_flow_test.py     # GUI 全流程自动测试

# 重新打包（需要 pip install pyinstaller）
python -m PyInstaller --onefile --windowed --manifest tests/dpi.manifest --name TyperSimulator app/TyperSimulator.py
cp dist/TyperSimulator.exe app/打字模拟器.exe

# 受限环境（不能起子进程/临时目录受限）下用包装器跑 PyInstaller：
PYTHONPATH=.pydeps python tests/_run_tool.py PyInstaller --onefile --windowed --manifest tests/dpi.manifest --name TyperSimulator app/TyperSimulator.py

# 如需签名（证书在当前用户证书库）：
powershell -Command "$c = Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert | Where-Object {$_.Subject -eq 'CN=你的证书名'}; Set-AuthenticodeSignature .\app\打字模拟器.exe -Certificate $c"
```

## 注意事项

- **高 DPI 屏幕**（如 125%/150% 缩放）：exe 已内置 PerMonitorV2 感知清单，界面按系统缩放比例清晰渲染不再发虚；日志第一行的 `dpi_mode=pmv2` 表示感知生效，若显示 `unaware` 说明被系统兼容性设置覆盖（右键 exe → 属性 → 兼容性 → 更改高 DPI 设置 → 勾"替代高 DPI 缩放行为"选"应用程序"）。
- 按键以 Unicode 方式发送，中文、全角标点、emoji 都支持；文件里的换行会按回车键。
- 打字时自动把系统定时器精度提到 1ms，高速度（几百字/秒）才能真正跑满。
- 吐字稳定性已加固（按键原子发出 + 硬输入微批次节流），速度拉满一般也不丢字；个别极慢的程序若仍丢字，把速度调低一些即可。
- **管理员权限运行的窗口**（如某些系统程序）收不到普通程序发的按键，需要本程序也以管理员身份运行。
- 部分游戏使用 DirectInput 读键盘，可能收不到模拟按键。
- F6 在个别程序里本身有快捷键（如浏览器切换焦点），如冲突可改源码里的 `VK_F6` 常量后重新打包。
